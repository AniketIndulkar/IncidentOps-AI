# IncidentOps AI v1.0: release notes

**Status:** ready to tag; not tagged. The tag, the recording and merging the stacked pull requests
are the owner's ([checklist](v1.0-checklist.md)).

IncidentOps triages production incidents: it retrieves the runbooks and postmortems that bear on an
incident, asks a model for a diagnosis that must cite them, adds the service's owner, on-call and
dependencies, and proposes a ticket that a person approves before anything is written. Every
failure ends in a named state, and `GET /status` says how degraded the service is.

## What is in v1.0

| Area | What it does | Since |
|---|---|---|
| Incidents API | create and read incidents, idempotency keys, `problem+json` errors | W01 |
| Extraction | the incident's fields as a typed result, with fixed review rules | W02 |
| Retrieval | hybrid (dense + BM25) over Markdown runbooks and postmortems in pgvector | W03, W04 |
| Diagnosis | causes that cite verbatim quotes, checked against the evidence; explicit `no_answer` | W04 |
| Knowledge graph | owner, on-call, dependencies and upstream fixes from Neo4j, as context (optional) | W05 |
| Attachments | screenshots and PDFs become citable text (text layer, OCR, vision transcript) | W06 |
| Triage workflow | a fixed LangGraph graph, the route and recommendation in code, PostgreSQL checkpoints, resume | W07 |
| Approval and memory | one approval gate per run, append-only audit trail, reviewer notes recalled as evidence | W08 |
| Tools | a ticket server over MCP whose writes need a signed approval; Jira and SOAP CMDB adapters | W08, W09 |
| Ops questions | text-to-SQL behind an allow-list, a validator, a read-only login and row-level security | W09, W10 |
| Identity and security | JWTs, four roles, ten permissions, tenants in the data layer, PII redaction, a model guard, injection flags | W10 |
| Quality | four evaluation layers, a CI gate, a model gateway with fallback and breakers, tracing | W11 |
| Reliability | bounded dependencies, recovery of runs left by a dead process, serialised writes, `GET /status` | W12 |

## Changed in the release week (W13)

- **Stale runs are recovered while the API runs**, every `INCIDENTOPS_STALE_RUN_SWEEP_S` seconds
  (default 60), not only at startup.
- **Reading a run, listing runs or attachments, and recording a decision no longer count against
  the model rate limit.** Only starting or resuming a triage, uploading an attachment and the
  analysis and ops endpoints do.
- **`docker-compose.yml` passes every setting** from `.env` to the API; a blank value means the
  default. Files the API writes go in a new `appdata` volume at `/var/lib/incidentops`.
- **A blank setting means its default everywhere** (`.env` or the environment); a blank number no
  longer fails to start the API, and a blank trace file no longer becomes the path `.`.
- New documentation: [README](../../README.md), [architecture](../architecture.md),
  [ADR index](../adr/README.md), [reports](../reports/README.md), [cost model](../cost-model.md),
  [known limitations](../known-limitations.md), [deployment guide](../deploy.md).

## Upgrading from a W12 deployment

1. `git pull`, then compare your `.env` with `.env.example` (settings were regrouped, none
   renamed).
2. If you used the bundled ticket server or a trace file, point them into the data volume:
   `INCIDENTOPS_TICKETS_DB=/var/lib/incidentops/tickets.db`,
   `INCIDENTOPS_TRACE_FILE=/var/lib/incidentops/traces.jsonl`.
3. `docker compose up -d --build`. There are no new migrations in W13.
4. `GET /status` should say `FULL` (or `REDUCED` with the reason, if an optional part is down).

## Measured

| | |
|---|---|
| One triage, real model | 6.5 s median, about $0.019 (assumed price) |
| 100 concurrent responders (simulated model) | 0 errors, triage P95 9.1 s |
| Diagnosis on 16 golden incidents | answers or declines correctly 15/16, citation precision 1.000 |
| Security regression suite | 170 tests in CI; 0 of 6 real-model injections followed |

Small, single-author datasets: read [the reports](../reports/README.md) and
[the limitations](../known-limitations.md) before relying on these numbers.

## Not in v1.0

Retention and expiry (idempotency keys, checkpoints, traces, runs waiting at the gate), a relevance
gate before diagnosis, an approximate vector index, a real identity provider or Langfuse connected
and measured, real provider limits under load. Each is on the [checklist](v1.0-checklist.md) with
the reason it waited.
