# v1.0 release checklist (AIENG-74)

Scope frozen on 17 Oct 2026 (W13 built early): no new features after
[the W13 design](../roadmap-w13.md). Every open item from the [ROADMAP risk list](../ROADMAP.md),
the weekly findings and the [reliability retrospective](../notes/reliability-retro.md) is classified
below. Numbers in brackets are ROADMAP risk numbers.

## Must-fix (done in W13, each with a test or a verification)

| Item | Why it cannot ship as is | Done |
|---|---|---|
| **Stale runs recovered only at startup** [48] | After a database blip, interrupted runs stay `running` until someone restarts the API | a periodic sweep (`INCIDENTOPS_STALE_RUN_SWEEP_S`) |
| **Deployment files are W01-era** | `docker-compose.yml` knows none of the W03–W12 settings and has no corpus step; a newcomer could not reach a working triage | rewritten and verified from clean (H54) |
| **README describes weeks, not the product** | A newcomer reads twelve weekly sections before learning how to run it | rewritten for a newcomer |

## Release gates owned by the user

- [ ] CI green on the stacked branches (#3 to #13; CI has not run on them since the pgvector image change in W03 [19]).
- [ ] Merge the stack in order.
- [ ] Tag `v0.1`, `v0.2` and `v1.0`.
- [ ] Record the walkthrough ([script](walkthrough-script.md)).
- [ ] Re-label the judge's calibration set, if the judge should ever gate [45].

## Deferred (worth doing, not needed for v1.0)

| Item | Reason to defer |
|---|---|
| Idempotency keys never expire [10] | Storage grows slowly (one row per create with a key); add a TTL job with retention policy |
| Checkpoint, trace and `llm_runs` retention [33] | Needs a retention policy decision (legal, not technical) |
| Runs waiting at the gate have no expiry or reminder [37] | Needs a notification channel; the run is safe while it waits |
| A relevance gate before diagnosis [23] | Off-corpus incidents are declined by the model (3 of 3 in W11); a score threshold needs more off-corpus data |
| BM25 stemming [24] | Small effect on this corpus; re-test on a larger one |
| HNSW vector index [20] | Exact scan is right below ~10,000 chunks |
| Ops data in its own database [38] | Closes the catalog-read gap; a deployment change, documented |
| Periodic re-measurement with a real provider under load [49] | Costs money; do it with a real account's limits before production |
| Updating an incident (lost-update protection) [15] | There is no update endpoint yet |

## Known limitations (documented in [known-limitations.md](../known-limitations.md))

Evaluation sets are small and single-author [7, 14, 18, 26, 30]; citations prove words, not claims
[22]; vision transcripts can misread faithfully and OCR can drop lines [28, 29]; routes inherit
noise from model-chosen counts [31]; a recommendation can rest on one reviewer's note [35]; the
approval secret and JWT key mint authority [36]; catalog reads depend on the SQL validator [38];
adapters are tested against fakes [39]; the static API token is an admin credential [41]; PII
detection is pattern-based [42]; the injection detector is a phrase list [43]; no real identity
provider or live Langfuse has been connected [44, 46]; the judge is reported, not gated [45];
prompt changes cost a real-model run [47]; real provider limits are unmeasured [49]; ticket
deduplication leans on the ticket system's search [50]; the reranker does not fit the 1 GB
deployment [25]; Neo4j is a second datastore [27].
