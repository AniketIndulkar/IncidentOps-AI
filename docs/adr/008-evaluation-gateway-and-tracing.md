# ADR-008: Layered evaluation with a calibrated judge, one gateway, traces, and a CI gate

- **Status:** accepted (W11, 17 Oct 2026)
- **Context tickets:** AIENG-64 to AIENG-68
- **Evidence:** [W11 findings](../../evals/generation/runs/2026-10-17-w11-findings.md),
  [dashboard](../../evals/dashboard.md), [W11 design](../roadmap-w11.md)

## Context

Ten weeks of measurements lived in one-off reports. Nothing stopped a change from making things
worse, model calls went to one model with nowhere to fall back, and a run could be reconstructed
only from scattered tables.

## Decision

1. **Four layers, each with a purpose**: retrieval, generation, workflow, system (plus security).
   Each has its dataset and metrics; the ones CI can measure offline have thresholds.
2. **RAGAS-style metrics, in our code**: deterministic answering, context recall and precision,
   citation precision; faithfulness and relevance by a versioned judge prompt.
3. **A judge is a signal with its agreement attached.** It is compared with labels before its
   numbers are used; below the agreement bar it is reported, not gated. Today it is below the bar.
4. **One gateway for every model call**: per-task routes, fallback only on failures another model
   could fix, a circuit breaker, a per-model rate limit, the answering model on record.
5. **Traces**: spans for runs, steps, model calls, retrieval and tools, one trace per run; JSONL
   and Langfuse exporters; a report that rebuilds a run.
6. **A CI gate** over the offline layers and the recorded generation run, failing any prompt
   change that comes without a refreshed real-model run.

## Why not the alternatives

- **One accuracy number.** It cannot say whether retrieval, the answer or the workflow broke.
- **RAGAS or DeepEval as libraries.** Large dependencies whose own model calls and prompts we would
  not version; their scores would move when they update.
- **Trust the judge.** At 31% agreement in its first version, its faithfulness score would have
  failed eleven good causes.
- **LiteLLM.** A second provider abstraction beside ours; our strict structured output, recorded
  attempts and guard depend on our interface. The routing here is small and tested exactly.
- **The Langfuse SDK.** One more dependency for what is a documented HTTP batch.
- **Real-model evals in CI.** CI has no key, and should not spend money on every push; the
  fingerprint rule forces a run only when a prompt changes.

## Consequences

- Changing any prompt now costs a real-model run (about $0.15 for generation, $0.04 per judge pass).
- The judge needs better labels (the user's, and more of them) before it can gate anything.
- Every model call has one more hop (the gateway) and a span; both are cheap.
- `evals/dashboard.md` is regenerated by every gate run.

## Revisit when

- The user has labelled the judged causes: recompute agreement, and gate on the judge if it passes.
- Production traffic exists: the system layer gets thresholds (latency, error rate, cost per run).
- A second provider is added: routes can then cross providers, not just models.
