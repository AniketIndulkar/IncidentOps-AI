# Week 6 write-up: multimodal evidence (AIENG-39 to AIENG-43)

Status on 17 Oct 2026: **built and measured**, as a pull request stacked on W05. Design, hypotheses
and both rules were committed before any extraction code ([roadmap-w06.md](../roadmap-w06.md)); the
numbers are in [the findings](../../evals/multimodal/runs/2026-10-17-multimodal-findings.md) and the
decision in [ADR-003](../adr/003-multimodal-routing.md).

## The result in five lines

1. Incidents now take **attachments** (PNG, JPEG, PDF): text is extracted at upload and the diagnosis
   can cite it as evidence `A1..An`, with the pixel box of the quoted lines when OCR read them.
2. **Text PDFs use their text layer, scans use OCR, images use a vision transcript**: on 28 questions,
   OCR answered 1 of 6 chart questions and 2 of 6 diagram questions; the transcript answered all.
3. **OCR keeps the words and loses the picture**, and it can drop a whole line without any low
   confidence score to warn you.
4. **The router I designed in advance was wrong** (9 of 14): text coverage makes a scanned page look
   like a chart. Routing on the file type is simpler and matched every asset here.
5. Six incidents ran end to end with real models; two diagnoses cited the attachment itself. 612 tests
   pass (2 opt-in tests skipped).

## Decisions, with why and why not

| Decision | Why | Why not the alternative |
|---|---|---|
| **Generated benchmark assets**, committed and regenerated byte for byte | Reproducible; answers can be made visible only as shapes or marks | Real screenshots are private; downloaded images are not ours to commit |
| **Diagram relations a model cannot guess** (`promo-engine`, `ledger-writer`) | Otherwise a text model answers from prior knowledge and OCR looks good | Real service names with obvious relations |
| **RapidOCR as an optional extra** | Local, free, models in the wheel, Python 3.13 | Tesseract needs a system install; cloud OCR costs and sends data out |
| **Only text is cited** | The W04 rule: every shown cause has checked provenance | Showing a vision model's answer with no quote |
| **Attachments outside the shared index** | They belong to one incident | Indexing them, which would leak them into other incidents' retrieval |
| **Type from bytes, size and page limits, decompression-bomb check, name as label** | An upload is untrusted input | Trusting the declared content type and file name |
| **Vision failure falls back to OCR** | Some text is better than none | Failing the upload |

## What the numbers taught

- "The extracted text contains the answer" is not the same as "a reader can answer from it": charts
  scored 6/6 on the first and 1/6 on the second.
- OCR errors are quiet. Spaces vanish, case flips, a letter goes missing (`biling-service`), a whole
  line disappears. The text model often reads through it; a quote from that text will look odd.
- A vision transcript is right far more often, and wrong in a more dangerous way: a plausible
  misreading (`mbznw`) that a citation then repeats faithfully.
- H18 to H22 held; H23 (my router) did not.

## What went wrong on the way

- I inserted a function between `@cache` and the function it decorated; a test about schema caching
  caught it.
- My first failover diagram drew the red cross over the label it was meant to mark, and pointed an
  arrow at nothing. I redrew it before writing any extraction code.
- I first called BM25 from synchronous code by stepping its coroutine by hand; replaced with plain
  `async`.

## What is still weak

- Synthetic, clean images. Real screenshots will hurt OCR more.
- No cross-check between OCR and transcript for the identifiers that matter.
- The price per token is assumed, so cost figures are estimates.
