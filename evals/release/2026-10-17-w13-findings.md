## The clean deployment

Two passes, each from an empty volume, following [deploy.md](../../docs/deploy.md) step by step:
configure, `docker compose up -d --build`, ingest and index the corpus, `GET /status`, a first
triage, a decision. Image layers came from the build cache; "clean" here means the data, not the
build.

**Pass 1** reached `FULL` and a triage at `awaiting_approval` in 7.2 s with a cited diagnosis. It
also found the gaps:

| Gap | Effect on a newcomer | Fix |
|---|---|---|
| Compose passed a hand-picked list of settings; tracing and the bundled ticket server were not on it | Setting them in `.env`, as the guide said, did nothing | every setting passed as `${VAR:-}`; `tests/test_deploy_config.py` fails if Settings, compose and `.env.example` drift apart |
| A blank setting from compose had to parse as its type | A blank number would stop the API from starting; a blank trace file became the path `.` (found while preparing the deployment) | `env_ignore_empty`, plus the existing blank validator |
| No writable place for files the API writes | The ticket server's database and a trace file had nowhere to live in the container | an `appdata` volume at `/var/lib/incidentops`, owned by the unprivileged user |
| `.env.example` listed the Neo4j settings twice and seven settings not at all | A newcomer could not discover them | regrouped, one entry per setting (test-guarded) |
| The guide promised a ticket; the short example goes to review and, without a ticket system, ends `approved` with no ticket | A correct run looks like a failure | the guide says what a first triage returns, and why |

**Pass 2**, with the ticket server and a trace file switched on through `.env` only: `FULL` with
tickets `ok`; the approval ended `actioned` with a ticket; `tickets.db` and `traces.jsonl` were in
the volume, owned by `app`. Then the guide's operating claims: data survives `docker compose down`
(the incident was still there after `up`), `docker compose down -v` deletes it (404 afterwards),
the documented `pg_dump` and `docker compose cp` backups work, and stopping the database turns
`GET /status` from `FULL` to `MANUAL` and back.

Idle memory, measured: API 225 to 245 MiB, PostgreSQL 25 to 28 MiB, Neo4j (empty) 349 MiB. The
API image is 644 MB.

## Found while writing the documents

| Finding | Classified | Why |
|---|---|---|
| The model rate limit covered every triage and attachment route, so reading a run, listing runs or attachments, and recording a decision used up the per-process budget (10 a minute by default). The W12 load test had raised the limit to a million, which hid it | **must-fix**, done: only the routes that call a model take the limit (`test_reading_and_deciding_do_not_spend_the_model_budget`, red then green) | a reviewer could be refused an approval because others were triaging |
| The Langfuse exporter sends with a synchronous client on the event loop (bounded at 5 s) | **deferred** [53] | optional, never connected to a real Langfuse; documented with the workaround (the JSONL file) |
| `GET /status` checks that retrieval is configured, not that the corpus is ingested | **deferred** [54] | an empty corpus ends every run in review, never in a wrong answer; the guide's step 4 covers it |

Checking every failure row of [architecture.md](../../docs/architecture.md) against the code also
corrected the page before it was committed: the injection reason code is `suspicious_evidence`,
diagnosis answers `no_evidence` without a model call when retrieval returns nothing, and an open
breaker on every model ends runs in `model_failed` rather than refusing to start them.

## The release

All three must-fixes from the checklist are done, and two more were found and fixed during the
week ([checklist](../../docs/release/v1.0-checklist.md)). The suite passes (961 tests: 959 passed,
2 skipped), ruff is clean, `alembic check` finds no drift, and the evaluation gate passes with the
recorded generation run (no prompt changed). Not done, by design: the `v0.1`, `v0.2` and `v1.0`
tags, the recording ([script](../../docs/release/walkthrough-script.md)), merging the stacked pull
requests, CI on the stack, Jira, any AWS deployment.

## Limits

- One machine; Docker Desktop's VM, not a server. The [Lightsail guide](../../docs/deploy-lightsail.md)
  was not re-run.
- The deployment was verified by the person (the assistant) who wrote the guide, which is the risk
  the W13 design named first: a guide reads clearer to its author.
- Memory was measured idle, not under load.
