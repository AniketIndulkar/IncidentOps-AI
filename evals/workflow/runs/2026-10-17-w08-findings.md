## What the fault scenarios found

1. **A malformed answer at the gate poisoned the run.** LangGraph stores an interrupt's answer in
   the checkpoint and replays it every time the node runs again. My `approval` node validated the
   answer and raised: so a bad value (sent straight to the graph, bypassing the API's validation)
   was replayed on every later decision, and even a correct approval failed the run. The gate now
   interrupts again with an error instead of raising, up to three bad answers. The API could never
   send such a value, but the graph is reachable from code, and the gate must hold there too.
2. **A model call cancelled with its step went unrecorded** (found in W07, fixed here). When one of
   the two parallel model steps raises, LangGraph cancels the other; if its call had returned, the
   `llm_runs` row was rolled back with the cancelled write. The record is now a shielded task, and
   the runner waits for outstanding records before it records the failure. In the scenarios, model
   calls made always equal calls recorded.
3. **"It worked but the reply timed out" is real.** The timeout scenario's server stored the ticket,
   then answered after the client had given up. The run failed honestly (`TicketTimeoutError`); the
   resume, through a restarted server, got the same ticket back (`created: false`). Without the run
   id as idempotency key this would be two tickets.

## What the memory check showed

- Without a note, all three incidents were `no_answer` and went to review: the corpus has nothing
  on printers, the image CDN or the VPN.
- With the reviewer's note, all three were answered from `M1` alone; two of three were then routed
  to **recommend**. **A single reviewer's note can now be the whole evidence for a recommendation.**
  The approval gate still stands between that and any action, and the proposed ticket lists the note
  as the evidence; but nothing marks "this rests only on a note". Candidate for W09/W10.
- Scope held: a note stored for `<service>-legacy` and for another tenant was never recalled.

## Limits

Reviewer identity is self-declared until W10. The memory check is three incidents written to have a
note-shaped answer; it shows that notes are used and scoped, not how often real notes are right.
The fault scenarios use scripted models: they test the workflow's handling, not a model's behaviour.
